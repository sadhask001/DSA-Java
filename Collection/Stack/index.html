Stack Fundamentals

The LIFO Principle: Last-In, First-Out

A Stack is a linear, restricted data structure that follows the LIFO (Last In, First Out) rule. Elements can only be added (pushed) and removed (popped) from a single designated location: the Top of the stack.

🌍 Real-World Mental Models:
  • A vertical spring-loaded stack of cafeteria cafeteria plates (you take from the top, you put onto the top).
  • Browser navigation back-button history (the most recently visited URL pops first).
  • Undo / Redo buffers in code editors (`Ctrl + Z`).
  • JVM Execution Call Stack (tracking active function frames and local parameters).

Overflow Condition

Occurs when attempting to push an item into an array-based stack that has already reached its maximum allocated capacity (top == capacity - 1).

StackOverflowError

Underflow Condition

Occurs when attempting to pop or peek from a completely empty stack (top == -1 or head == null).

EmptyStackException

Core Operations ($O(1)$ Time)

Stack Interface Specification

Every standard stack operation runs in strict $O(1)$ time complexity because no elements need to be shifted in memory.

Method Signature Description Time Complexity Space Complexity
push(E item) Pushes an item onto the top of this stack. O(1) O(1)
pop() Removes and returns the object at the top. O(1) O(1)
peek() Looks at the top object without removing it. O(1) O(1)
isEmpty() Tests if this stack has no elements. O(1) O(1)
size() Returns the current number of elements. O(1) O(1)

Array-Based Stack Implementation

Fixed Capacity Memory Buffer

An array-based stack uses an internal fixed array and an integer pointer top initialized to -1. When pushing, increment top and assign the value. When popping, read the value and decrement top.

public class ArrayStack {
    private int[] arr;
    private int top;
    private int capacity;

    public ArrayStack(int capacity) {
        this.capacity = capacity;
        this.arr = new int[capacity];
        this.top = -1; // Empty state
    }

    public void push(int x) {
        if (top == capacity - 1) {
            throw new RuntimeException("Stack Overflow: Capacity exceeded!");
        }
        arr[++top] = x;
    }

    public int pop() {
        if (isEmpty()) {
            throw new RuntimeException("Stack Underflow: Stack is empty!");
        }
        return arr[top--];
    }

    public int peek() {
        if (isEmpty()) throw new RuntimeException("Stack is empty!");
        return arr[top];
    }

    public boolean isEmpty() { return top == -1; }
    public int size() { return top + 1; }
}

Linked List-Based Stack Implementation

Dynamic Growing Stack

A Linked List-based stack eliminates fixed-size overflow limits by allocating nodes dynamically on the heap. We push and pop at the head of the list to preserve strictly $O(1)$ operations.

public class LinkedListStack {
    private static class Node {
        int data;
        Node next;
        Node(int data) { this.data = data; }
    }

    private Node top = null; // Head of list represents stack Top
    private int count = 0;

    public void push(int val) {
        Node newNode = new Node(val);
        newNode.next = top; // Insert at head
        top = newNode;
        count++;
    }

    public int pop() {
        if (top == null) throw new RuntimeException("Stack Underflow!");
        int val = top.data;
        top = top.next; // Remove head
        count--;
        return val;
    }

    public int peek() {
        if (top == null) throw new RuntimeException("Stack is empty!");
        return top.data;
    }

    public boolean isEmpty() { return top == null; }
    public int size() { return count; }
}

Stack in the Java Collections Framework

java.util.Stack vs ArrayDeque

Java provides a legacy java.util.Stack class, but modern Java best practices strongly recommend using Deque<E> stack = new ArrayDeque<>() instead.

Legacy: java.util.Stack

  • Extends Vector (violates single responsibility, allows random index insertions like stack.add(0, x)!).
  • Every method is synchronized, introducing heavy thread contention overhead even in single-threaded environments.

Recommended: ArrayDeque

Deque<Integer> stack = new ArrayDeque<>();
stack.push(10);
stack.push(20);
int val = stack.pop(); // 20
int top = stack.peek(); // 10

Faster than Stack, no thread locks, circular buffer backing array with automatic resizing.

Real-World Applications

1. Balanced Parentheses Validation

Match opening brackets (, {, [ by pushing them onto the stack. When encountering a closing bracket, verify the top of the stack matches before popping.

public boolean isValid(String s) {
    Deque<Character> stack = new ArrayDeque<>();
    for (char c : s.toCharArray()) {
        if (c == '(') stack.push(')');
        else if (c == '{') stack.push('}');
        else if (c == '[') stack.push(']');
        else if (stack.isEmpty() || stack.pop() != c) return false;
    }
    return stack.isEmpty();
}

2. Expression Conversion: Infix to Postfix (RPN)

Compilers use stacks to convert human-readable infix expressions (e.g. A + B * C) into postfix notation (A B C * +) using operator precedence rules, making expression trees straightforward to evaluate.

Monotonic Stack Pattern

The Next Greater Element Technique

A Monotonic Stack maintains its elements in strictly sorted order (either strictly increasing or strictly decreasing). It solves range queries like "find the next greater element for every index" in a single $O(N)$ pass instead of brute-force $O(N^2)$.

public int[] nextGreaterElement(int[] nums) {
    int n = nums.length;
    int[] result = new int[n];
    Deque<Integer> stack = new ArrayDeque<>(); // Stores indices

    for (int i = n - 1; i >= 0; i--) {
        // Pop all elements smaller than current
        while (!stack.isEmpty() && nums[stack.peek()] <= nums[i]) {
            stack.pop();
        }
        result[i] = stack.isEmpty() ? -1 : nums[stack.peek()];
        stack.push(i);
    }
    return result;
}
