The Infamous Integer Overflow Bug

For decades, textbooks wrote binary search midpoint calculation as: 

// BUGGY FORMULA:
int mid = (low + high) / 2; // Vulnerable to 32-bit signed integer overflow!

In 2006, Joshua Bloch documented that when \(low + high > 2^{31} - 1\) (\(\approx 2.14 \times 10^9\)), the sum overflows into a negative value, triggering an ArrayIndexOutOfBoundsException. The mathematically identical and overflow-safe formula is: 

// OVERFLOW-SAFE FORMULA:
int mid = low + (high - low) / 2;
// Alternatively using unsigned bit shift:
int mid = (low + high) >>> 1;

The Three Fundamental Binary Search Templates

Template 1: Exact Element Search (low <= high)

Used when searching for a definite target in an array without duplicates. Ends when low > high. 

public static int binarySearchExact(int[] arr, int target) {
    int low = 0, high = arr.length - 1;
    while (low <= high) {
        int mid = low + (high - low) / 2;
        if (arr[mid] == target) return mid;
        else if (arr[mid] < target) low = mid + 1;
        else high = mid - 1;
    }
    return -1;
}

Template 2: Boundary / Inflection Point (low < high)

Used when finding the boundary where a condition flips (e.g., minimum in rotated array, first bad version). Search space is never empty; terminates with low == high. 

public static int findMinInRotated(int[] nums) {
    int low = 0, high = nums.length - 1;
    while (low < high) {
        int mid = low + (high - low) / 2;
        if (nums[mid] > nums[high]) {
            low = mid + 1; // Inflection point lies strictly in right half
        } else {
            high = mid;    // mid could be the minimum, preserve it
        }
    }
    return nums[low];
}

Template 3: Neighbor Comparisons (low + 1 < high)

Guarantees search space has at least 3 elements so mid - 1 and mid + 1 are always valid without boundary checks. Useful for Peak Element (LeetCode 162).

Lower Bound & Upper Bound

Lower Bound (\(\ge \text{target}\))

Returns the first index where \(arr[i] \ge \text{target}\). 

public static int lowerBound(int[] arr, int target) {
    int low = 0, high = arr.length;
    while (low < high) {
        int mid = low + (high - low) / 2;
        if (arr[mid] >= target) high = mid;
        else low = mid + 1;
    }
    return low;
}

Upper Bound (\(> \text{target}\))

Returns the first index where \(arr[i] > \text{target}\). 

public static int upperBound(int[] arr, int target) {
    int low = 0, high = arr.length;
    while (low < high) {
        int mid = low + (high - low) / 2;
        if (arr[mid] > target) high = mid;
        else low = mid + 1;
    }
    return low;
}

2D Matrix Searching

Type 1: Row-Major Sorted Matrix (LeetCode 74)

Each row is sorted, and the first integer of each row is greater than the last of the previous. Treat the \(m \times n\) grid as a virtual 1D array of length \(m \cdot n\): \[\text{row} = \text{mid} / n, \quad \text{col} = \text{mid} \bmod n\] Time complexity: \(O(\log(m \cdot n))\), Space: \(O(1)\).

Type 2: Independent Row & Column Sorted (LeetCode 240)

Start at the Top-Right corner \((0, n - 1)\). If \(matrix[r][c] > \text{target}\), prune the entire column \(c\) (\(c--\)). If \(matrix[r][c] < \text{target}\), prune row \(r\) (\(r++\)). Runs in linear \(O(m + n)\) time!

Binary Search on Answer Space

One of the most powerful paradigms in competitive programming and FAANG interviews. When asked to "minimize the maximum" or "maximize the minimum", check if the feasibility function canAchieve(speed) is monotonic:

If canAchieve(k) is TRUE, then canAchieve(k + 1), canAchieve(k + 2)... are also TRUE.
This monotonicity allows binary searching directly on the numeric answer range [1, maxPile]! 

// Koko Eating Bananas (LeetCode 875)
public int minEatingSpeed(int[] piles, int h) {
    int low = 1, high = 1_000_000_000;
    while (low < high) {
        int speed = low + (high - low) / 2;
        if (canEatAll(piles, speed, h)) {
            high = speed; // Try smaller speed
        } else {
            low = speed + 1;
        }
    }
    return low;
}
