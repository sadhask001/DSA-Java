Hashing & Hash Tables

Hashing is an algorithmic paradigm that maps arbitrary keys to fixed-size integer indices in constant average time \(O(1)\). Dive deep into polynomial hash codes, open addressing vs separate chaining, Java 8 Red-Black Tree treeification, and the critical equals() / hashCode() contract.

Time & Space Complexity

Under the Simple Uniform Hashing Assumption (SUHA), each key is equally likely to hash to any of the \(m\) slots, resulting in blistering \(O(1)\) average-case operational complexity.

O(n) / O(log n)*

*Note: In Java 8+, if a bucket's chain length exceeds 8 nodes and table capacity \(\ge 64\), the linked list converts to a balanced Red-Black Tree, capping worst-case lookups at \(O(\log n)\).

Anatomy of a High-Quality Hash Function

A hash function maps an arbitrary object \(K\) to an integer. A production-grade hash function must satisfy four non-negotiable criteria:

  • Determinism: Given the same input, it must always return the exact same integer hash code within the program run.
  • Uniform Distribution: It must disperse keys uniformly across all available buckets to prevent clustering and chain bottlenecking.
  • Speed: Computing the hash must execute in \(O(1)\) time relative to the size of the key.
  • Avalanche Effect: Flipping a single bit in the key should alter approximately 50% of the bits in the output hash code.

Polynomial Rolling Hash (Standard for Strings)

For strings of characters, standard implementations use a polynomial rolling hash with a prime multiplier \(p\) (commonly 31 or 37): 

// Standard Java String.hashCode() implementation: s[0]*31^(n-1) + s[1]*31^(n-2) + ... + s[n-1]
public static int computeStringHashCode(String s) {
    int h = 0;
    for (int i = 0; i < s.length(); i++) {
        h = 31 * h + s.charAt(i); // 31 * h can be optimized by JVM as (h << 5) - h
    }
    return h;
}

Why 31? 31 is an odd prime, so multiplication does not lose information (multiplying by an even number shifts bits left, dropping high bits). Furthermore, modern compilers optimize 31 * i into bit-shift operations: (i << 5) - i.

Collision Resolution Techniques

By the Pigeonhole Principle, since keyspace is virtually infinite and bucket array size \(m\) is finite, collisions are mathematically inevitable.

1. Separate Chaining

Each bucket in the array holds the head of a linked list (or balanced BST). Colliding items are appended to the bucket's list.

Pros: Simple deletion; load factor \(\alpha\) can exceed 1.0; table never overflows.
Cons: Pointer overhead; poor CPU cache locality due to heap node hopping.

2. Linear Probing

If slot \(h(k)\) is occupied, probe sequentially: \(h(k, i) = (h(k) + i) \bmod m\).

Pros: Superior CPU cache locality; zero pointer overhead.
Cons: Primary clustering (long contiguous runs of occupied slots slow down lookups).

3. Double Hashing

Uses a secondary hash function for probe offset: \(h(k, i) = (h_1(k) + i \cdot h_2(k)) \bmod m\).

Pros: Virtually eliminates primary and secondary clustering.
Cons: Requires two good hash functions; \(h_2(k)\) must be coprime to \(m\).

Deep Dive: Java HashMap Internals

Java's java.util.HashMap is one of the most engineered data structures in the JDK. Here is how it operates under the hood:

1. The Table and Power-of-Two Sizing

The backing storage is an array of nodes: Node<K, V>[] table. In Java, table capacity is always a power of two (\(2^n\), e.g., 16, 32, 64). This allows the expensive modulo operator hash % capacity to be replaced with lightning-fast bitwise AND: 

// Faster bitwise equivalence: when capacity is power of 2:
int index = (capacity - 1) & hash;
// Example: capacity = 16 (0001 0000), capacity - 1 = 15 (0000 1111)
// (hash & 15) isolates the lowest 4 bits, exactly mirroring hash % 16

2. The Hash Perturbation Function

Because (capacity - 1) & hash inspects only the lowest bits, poor hash codes could collide heavily. Java applies a perturbation step to XOR the higher 16 bits into the lower 16 bits: 

static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}

3. Load Factor & Rehashing

  • Default Initial Capacity: 16
  • Default Load Factor (\(\alpha\)): 0.75 (optimal trade-off between time and space)
  • Threshold: \(\text{capacity} \times \text{loadFactor} = 16 \times 0.75 = 12\) elements.
  • When size > threshold, the table doubles to \(2 \times \text{capacity}\) (e.g., 32). In Java, elements either stay at their current index i or move to i + oldCapacity, tested by a single bit (hash & oldCapacity) == 0!

4. Java 8+ Treeification

To defend against Hash Collision DoS attacks where an attacker crafts keys with identical hash codes, Java 8 replaces long linked lists with balanced Red-Black Trees (TreeNode<K,V>):

Constant Value Description
TREEIFY_THRESHOLD 8 When a single bucket chain exceeds 8 nodes, it is converted to a Red-Black Tree.
UNTREEIFY_THRESHOLD 6 When nodes in a bucket drop to 6 during resizing or deletion, it converts back to a linked list.
MIN_TREEIFY_CAPACITY 64 Treeification will NOT occur unless total table capacity is at least 64. Below 64, it resizes instead.

The equals() and hashCode() Contract

Whenever you use a custom object as a HashMap key or in a HashSet, you MUST adhere to the official Java Object specification:

1. If two objects are equal via a.equals(b) == true, their hash codes MUST be equal: a.hashCode() == b.hashCode().

2. If two objects have equal hash codes, they are NOT REQUIRED to be equal via equals() (this is merely a hash collision).

3. If you override equals(), you MUST override hashCode(). 

class Student {
    private int id;
    private String name;

    public Student(int id, String name) {
        this.id = id;
        this.name = name;
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        Student student = (Student) o;
        return id == student.id && Objects.equals(name, student.name);
    }

    @Override
    public int hashCode() {
        return Objects.hash(id, name);
    }
}

Complete Custom HashMap in Java

Below is a robust, production-quality implementation of a generic MyHashMap<K, V> utilizing separate chaining with dynamic load factor rehashing. 

import java.util.LinkedList;

public class MyHashMap<K, V> {
    private static class Node<K, V> {
        K key;
        V value;
        Node(K key, V value) {
            this.key = key;
            this.value = value;
        }
    }

    private int capacity;
    private int size;
    private static final double DEFAULT_LOAD_FACTOR = 0.75;
    private LinkedList<Node<K, V>>[] buckets;

    @SuppressWarnings("unchecked")
    public MyHashMap(int initialCapacity) {
        this.capacity = initialCapacity;
        this.size = 0;
        this.buckets = new LinkedList[capacity];
        for (int i = 0; i < capacity; i++) {
            buckets[i] = new LinkedList<>();
        }
    }

    public MyHashMap() {
        this(16);
    }

    private int getBucketIndex(K key) {
        int hashCode = (key == null) ? 0 : key.hashCode();
        return Math.abs(hashCode) % capacity;
    }

    public void put(K key, V value) {
        int bi = getBucketIndex(key);
        LinkedList<Node<K, V>> bucket = buckets[bi];

        for (Node<K, V> node : bucket) {
            if ((key == null && node.key == null) || (key != null && key.equals(node.key))) {
                node.value = value; // update existing key
                return;
            }
        }

        bucket.add(new Node<>(key, value));
        size++;

        if ((double) size / capacity > DEFAULT_LOAD_FACTOR) {
            rehash();
        }
    }

    public V get(K key) {
        int bi = getBucketIndex(key);
        for (Node<K, V> node : buckets[bi]) {
            if ((key == null && node.key == null) || (key != null && key.equals(node.key))) {
                return node.value;
            }
        }
        return null;
    }

    public V remove(K key) {
        int bi = getBucketIndex(key);
        LinkedList<Node<K, V>> bucket = buckets[bi];
        for (int i = 0; i < bucket.size(); i++) {
            Node<K, V> node = bucket.get(i);
            if ((key == null && node.key == null) || (key != null && key.equals(node.key))) {
                bucket.remove(i);
                size--;
                return node.value;
            }
        }
        return null;
    }

    @SuppressWarnings("unchecked")
    private void rehash() {
        LinkedList<Node<K, V>>[] oldBuckets = buckets;
        capacity *= 2;
        buckets = new LinkedList[capacity];
        for (int i = 0; i < capacity; i++) {
            buckets[i] = new LinkedList<>();
        }

        size = 0;
        for (LinkedList<Node<K, V>> bucket : oldBuckets) {
            for (Node<K, V> node : bucket) {
                put(node.key, node.value);
            }
        }
    }

    public int size() { return size; }
    public boolean containsKey(K key) { return get(key) != null; }
}
